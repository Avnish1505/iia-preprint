OmitBench

Measuring what AI coding agents quietly leave out of patches they report as complete.

A benchmark and deterministic detector for silent omissions in AI coding agent patches, built on a 310-instance corpus spanning eight Python libraries. Defects are introduced by hunk-deletion-free mutation injection across three classes — ABSENT, UNWIRED, and STUB — so that an omission is never visible as a missing diff hunk.

Headline result — negative

The pre-registered deterministic detector (P1) lost to the LLM-judge baseline (B5), at a paired MCC of −0.202 with a confidence interval excluding zero. The result is published as measured. Detectors that failed to clear the pre-registered bar were retired rather than re-tuned.

A follow-up experiment isolated why. Requirement extraction, not detection, is the binding bottleneck: literal-pipeline extraction scores MCC −0.935, meaning the pipeline cannot reliably recover what a patch was supposed to contain before any detector is asked to judge it.

Live agent trajectories were collected across tqdm, PyCQA/bandit, marshmallow and mkdocs. In that real-world subset every agent succeeded, so only false-positive rate was measurable — reported as a limitation rather than folded into the headline. The repository ships a CI gate enforcing a precision floor of 0.80.

Detecting Silent Implementation Integrity Failures in AI-Generated Code

A static analysis approach.

When an AI coding agent reports that it has finished wiring a safety check into an execution path, the resulting code may parse, import, and pass its existing tests while the check itself never runs. The structure is present, the connection is not, and no error is raised. This paper describes the Implementation Integrity Analyzer (IIA), a deterministic static analyzer that reads a Python AST and looks for three signatures of that failure.

  • Scaffolded functions — bodies containing only recognized scaffold markers: pass, an ellipsis, a bare docstring, or NotImplementedError.
  • Intent–implementation mismatch — a stated capability with no corresponding identifier anywhere in the file.
  • Unwired safety gates — a safety-critical function defined but never called from the operation it guards.

Ten of the fifteen scenarios are classified correctly. The four false positives and one false negative fall entirely in a hard group written to sit outside the analyzer's documented boundary, and each maps to a limitation recorded before the benchmark was run. The false negative is the informative one: the gate is called, but inside a branch that does not execute first — presence in a call set is not the same as running before the guarded action.

The comparison baseline is a string-presence check. It degenerates to a single-class predictor, because a function's name always appears in its own definition line, leaving its precision and MCC mathematically undefined rather than merely low. The benchmark is small and self-authored; the results characterize one detector on one corpus and do not estimate real-world prevalence.
